# CAID Project Steering

Project: CAID – Canvas AI Intrusion Detection System

## Development Instructions

1. **Audience**: The user is a Python beginner. Explain code in simple, clear language with beginner-friendly terminology.

2. **Technology Stack**: Use Python, Streamlit, Pandas, NumPy, Scikit-learn, and Plotly. Do not introduce additional frameworks without explanation.

3. **Project Type**: Build a modular, professional cybersecurity application for security monitoring and anomaly detection.

4. **Data**: Use only synthetic security logs for demonstrations. Never use or connect to real Canvas infrastructure.

5. **Ethical Boundaries**: 
   - Never attack or connect to real Canvas infrastructure
   - Never fabricate facts about the actual Canvas incident
   - Clearly distinguish between confirmed incident facts and simulated scenarios

6. **Machine Learning**: Use explainable ML techniques with evidence-based risk classification. Clearly explain model limitations.

7. **Architecture**: Separate concerns - frontend, backend, AI, ML, and data processing logic should be in distinct modules.

8. **Validation**: Always validate uploaded files and handle errors gracefully. Never execute uploaded content.

9. **Code Quality**: Write clean, commented, maintainable code. Include clear explanations of important code sections.

10. **Testing**: Test each feature before considering it complete. Use pytest for automated testing.

11. **File Management**: Never overwrite working files without reviewing them first. Preserve existing functionality.

12. **Terminal Commands**: Explain every terminal command before asking the user to run it.

13. **Avoid Hardcoding**: Do not hardcode fake detection results or fake AI confidence percentages. Calculate results from actual data.

14. **Transparency**: Clearly identify limitations and assumptions in the implementation.

15. **Documentation**: Maintain clear documentation for each module and feature.
