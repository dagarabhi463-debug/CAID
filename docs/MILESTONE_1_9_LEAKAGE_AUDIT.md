# CAID Milestone 1.9 — Leakage Audit Report

**Date:** 2026-11-12 · Evidence: `data/independent/leakage_audit.json`
(generated by `scripts/leakage_audit_1_9.py`, re-runnable).

Scope: every model input channel — IP prefixes and IP-derived features,
user identifiers, event identifiers, row ordering, timestamp patterns,
synthetic generation sequence, duplicates/near-duplicates, and features
derived from evaluation labels — audited on BOTH the legacy dataset
(`data/raw/*`, `data/processed/evaluation_data.csv`) and the new
independent datasets (`data/independent/*`).

## Confirmed leakage in the LEGACY pipeline (documented, not hidden)

| # | Channel | Evidence | Severity | Status |
|---|---------|----------|----------|--------|
| L1 | `source_ip` prefix → label | Legacy generator assigns `192.0.2.`=normal, `198.51.100.`=suspicious, `203.0.113.`=high_risk deterministically. NMI(prefix,label)≈1.0 on `legacy_eval` and `legacy_normal` (crosstab: each prefix is ~100% one label). `ip_class` is derived from these prefixes. | critical | confirmed — superseded by independent datasets; legacy files retained for backward compatibility only |
| L2 | `suspicious_ip_class` rule | Default rule condition `ip_class == 'suspicious' or 'high_risk'` hard-coded the synthetic label names — the rules channel received the label directly. | critical | **fixed** — rule removed from `_create_default_rules` (still addable manually); `rule_condition_label_reference` finding now `not_present` |
| L3 | Hour / `after_hours` / `token_age_minutes` | Legacy suspicious/high_risk generators used disjoint hour windows, after-hours rates and token-age ranges → single-feature label separability. | high | confirmed on legacy; **mitigated** in independent generator (overlapping ranges; `after_hours` derived from timestamp) |
| L4 | `is_sensitive_event` feature + event types | Legacy high_risk used exclusive event types (`grade_download`, `student_export`, `course_export`, `bulk_download`); `is_sensitive_event` is an ML feature. | high | confirmed on legacy; **mitigated** — independent holdout shows sensitive types under all labels (verified by test `test_is_sensitive_event_overlap_in_holdout`) |

## Channels audited — independent datasets (all clear)

| Channel | Method | Result |
|---------|--------|--------|
| IP prefix → label | NMI + crosstab per split | `not_present` on all 4 splits (NMI < 0.5 threshold; roughly uniform label×prefix) |
| Numeric features vs label | Single-feature ROC-AUC distance from 0.5 | api_requests ≈0.97–0.99, data_mb ≈0.97 — **expected behavioral separability, not identity leakage**: these are the detection signal itself. Reported for transparency, classified `info` |
| Categorical features (user_id, source_ip, event_type, role, ip_class) | Category-conditional label deviation | max score ≈0.08–0.12 — no category determines label |
| Row ordering | Positive rate first vs second half | gap < 0.15 on all splits (`not_present`) |
| Timestamp patterns | Row-index↔timestamp correlation, hour bands | no ordering artifact; hour bands overlap across labels |
| Generation sequence | Seeded `default_rng(1900)`; per-event label draws from user propensity | labels interleaved within users; no block structure |
| Duplicates / near-duplicates | Exact-row check across all splits | 0 duplicates (manifest `quality`) |
| Cross-split entity leakage | holdout-only cohorts vs train | 0 holdout-only users/IPs in train/calibration/validation |
| Cross-split row overlap | shared (user,ip,timestamp,event,features) keys | small count reported as `info` — legitimate recurrence of persistent entities |
| `label` column → features | `engineer_features` feature list inspection | `label` not a feature; `ip_class` engineered but NOT in ML feature list (only reachable via rules — and the only rule using it was removed) |

## Residual risks (documented, accepted for synthetic scope)

1. **Numeric feature separability is high by design** — the independent
   generator still produces statistically distinct behavior classes;
   AUC ~0.93 is a property of the synthetic task difficulty, not leakage.
2. `ip_class`/`is_sensitive_event` remain engineered columns; `ip_class`
   now has no consumer in default rules but persists in the schema.
3. Legacy datasets retain all confirmed leaks (L1–L4) — they are kept only
   for regression compatibility and must not be used for generalization
   claims.
4. Entity-frequency channels (`ip_event_count`,
   `event_type_frequency`, `user_*`) are fitted on train normals; unseen
   entities get documented typical-entity fallbacks (Milestone 1.8.1) —
   audited, no label path.
