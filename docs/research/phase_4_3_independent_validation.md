# Phase 4.3 — Independent Detection Validation

**Date:** 2026-11-12 · **Pipeline evaluated:** production batch stack `analyze_session_intelligence` (v2_0 profile, fingerprint-checked calibration `cal-20261112T035409Z-2962264f`) · **No retraining, no threshold/fusion changes, no holdout tuning.**

## 1. Dataset provenance

The repo's labeled CSVs under `data/raw` are the *internal reproducibility* set — the Milestone 2.7 report explicitly states `independent_validation: not_performed_current_data_only`. The **independent dataset is `data/independent_v2`**, generated by `data/generate_independent_datasets_v2.py` (seed 20260220, base date 2026-01-05) and removed from the working tree in cleanup commit `1744782`; it was **recovered read-only from git `bfdca25`** into a temp dir for this evaluation — it was NOT restored to the repo and no files were modified.

Splits (manifest `dataset_manifest.json`):

| Split | Rows | Labels (normal/suspicious/high_risk) | Purpose |
|---|---|---|---|
| train | 3000 | 2335 / 411 / 254 | model + baseline fitting (entity cohort `user_000–047`) |
| calibration | 800 | 706 / 60 / 34 | threshold calibration |
| validation | 800 | 642 / 111 / 47 | validation |
| **holdout** | **1500** | **1065 / 274 / 161** | **final eval — used once here** |

Entity cohorts: `shared_users` = user_000–047 (same cohort as train/val), `holdout_only_users` = user_h00–h15 (16 users disjoint from training). IPs overlap across splits by design (shared infrastructure).

**Overlap check (fresh):** holdout contains all 48 shared users → the holdout is **NOT fully entity-disjoint**; only the `user_h*` subset (350 rows) is user-disjoint. This is reported honestly — see §4.

Labeling methodology: synthetic generator assigns `normal`/`suspicious`/`high_risk` by scenario construction; labels are event-level ground truth for evaluation only (stripped in production streams). Leakage audit (`leakage_audit.json`) previously verified per-split identifier/label balance and monotonic explicit sessions.

## 3. Comparison with prior evidence

- `reports/fusion_evaluation.json` + `detection_quality.json` (internal reproducibility splits of `data/raw`): combined holdout F1 ≈ 0.96–0.99, near-zero FPR — **optimistic vs. independent data**.
- Prior `eval_results_v2.json` (v1.9 baseline on this same independent_v2 holdout): precision 0.889, recall 0.499, FPR 0.025, ROC-AUC 0.881.
- **Current v2.0 stack on identical holdout:** recall nearly doubled (0.94) but precision halved (0.497) and FPR rose ~15× (0.389). The v2 fusion weights favor sensitivity; on out-of-distribution synthetic data the cost is a high false-alarm rate.

## 4. Honest assessment & leakage risks

- **This is still synthetic data.** independent_v2 was produced by a generator written by the same project; distribution similarity to `data/raw` is high (same schema, same event vocabulary, overlapping IPs, overlapping user cohort). Results bound expected performance on *similar* synthetic traffic — they do NOT establish real-world effectiveness.
- **Partial entity leakage by design:** 48/64 users in holdout also appear in train/validation (cohort design, documented in manifest). The user_h* slice mitigates this and shows the same pattern.
- **No real-world holdout exists.** No authorized independent real dataset is available; per roadmap rules none was fabricated.
- **Thresholds were NOT tuned** on this holdout; reported numbers are the frozen production operating point.
- Confusion matrices per channel + combined (overall, holdout-only, shared-user slices) are in `reports/detection_confusion_matrices/` (33 CSVs).
